Resolution — what we built to sharpen Sigma, and what's left

The treated corpus is an instance; every "categorize Sigma" tool is really a resolution instrument. Five axes, claim → structure → behavior.

canon · exploration · 2026-06-21 · the seed question, verbatim, beside its developed answer

the question, verbatim
So I was thinking a lot of our general work with canon is an instance. All of the Sigma work depends on the datasets we ran to help shape the structure we extract from Sigma, with other data the treated sigma may be different. And not just the data but the constructions we built to help belnap/SKOS/FCA to parse the data by doing things that, hopefully, increase resolution. — the seed, 2026-06-21

Yes — catch-set grounding (catch_set.py) plus the ground_lattice arbiter is one of them, and the highest-resolution one on the "what does a rule detect" axis. But the constructions aren't a flat list. They're resolution instruments stacked on five axes, each trading a lossy representation for a finer one — and the move that runs through all of them is the same: claim → structure → behavior.

First: "it's an instance" is canon's own thesis, turned inward

The treated Sigma corpus isn't a fixed truth — it's a derived result, warranted only relative to its inputs: (corpus@cid, code@sha, labels). That's the warrant-is-relational principle applied to our own work, not a weakness. The construction that makes the instance-ness explicit is the treatment manifest (treatment_pipeline.py): it pins the producing state, and — the part that answers the question directly — it lets you diff two result-CIDs when you swap an input.

That diff is the measurement of "how much of this is an instance vs stable structure." Managing instance-contingency and increasing resolution turn out to be the same activity, seen from two sides.

The precise cut — not all the treatment is an instance. The structural half (content_signature, the lattice structure, the Belnap carrier, the mapping grades) is corpus-free, therefore portable — it doesn't move with the data. Only the behavioral half (catch-set, fidelity) is the instance: corpus-bound, capped by data shape. That's the actionable line — machinery sharpens the portable structural half (invest freely, no data needed: content_digest); only data moves the data-bound behavioral half (more / better-shaped corpora).

The five axes of resolution

Axis 1 — what does a rule detect?

tag  →  FCA concept-key  →  IR content_signature  →  catch-set
claim       field-set            structure              behavior        (lossy ───────────────────────────────────► fine)
  • tag (attack.tXXXX) — the author's claim. Lossiest: 79 rules claim T1003.001, 2 catch.
  • FCA concept-key (audit.py) — field-SET, value-blind. A resolution floor, not a booster: it over-collapses (32 distinct macOS detections → 1). This is what motivated the finer keys.
  • IR content_signature (rule_ir.py) — the actual clauses + values, corpus-free.
  • catch-set (catch_set.py, just built) — what's actually caught, corpus-grounded. Highest resolution — but data-contingent: this is the "instance."

Axis 2 — how do two rules relate?

binary dedup  →  SKOS-graded lattice  →  tightness grade  →  behavioral co-catch
same/not       exact/broad/narrow/related   IDF-weighted [0,1]      the arbiter
  • rule_lattice.py — exact / close / broad / narrow / related: a navigable order, not a collapse.
  • tightness (IDF-weighted Jaccard) — continuous; IDF is the entropy-analog: sharing a rare clause counts more than a ubiquitous one.
  • atom_implication.py — the same relation at the atom altitude.
  • ground_lattice (just built) — the arbiter: cross-tabs structural × behavioral to locate exactly where structure under- or over-resolves. The finding: behavioral synonyms are structurally related, not exact → dedup under-resolves.

Axis 3 — the carrier (state of knowledge)

boolean  →  Belnap four-valued  (None ≠ True ≠ False ≠ Both)

"Didn't look" (None) vs "looked, clean" (False) vs "contradiction" (Both) — the resolution that SQL-NULL→False destroys. (carrier in provenance.)

Axis 4 — cross-schema mapping fidelity

exact-or-nothing  →  SKOS-graded + load-bearingness gate

vocab.py / ocsf_*.py grade the mapping and gate demotion on whether the difference is load-bearing on this detection — an unused-field mismatch is inert, not a penalty.

Axis 5 — why did a rule miss? (resolution on the negative space)

silent  →  typed cause  →  assembly-level
        missing-telemetry / logic-gap / allowlist     instruction altitude

fidelity.py assigns a structured cause; assembly_diagnosis.py takes it down to the instruction level — resolution applied to the rules that didn't fire.

So one of these was just built (axes 1–2, the behavioral end), and it's the one that exposed the resolution gap between all the others: structure says related where behavior says synonym.

What else can sharpen resolution

In rough priority, each tied to a real gap:

  • Filter-aware + value-aware structural keys (the queued content_digest). The two finest corpus-free keys are still lossy: FCA is value-blind, clause_set is positive-only (filter-blind). Both verified to over-group (an svchost filter pair; a Linux EXECVE keyword trio). Cleanest next booster — raises axis-1/2 resolution with no new data.
  • Catch-profile, not catch-set (behavioral, new). The set records which instances fired; it can't tell apart two rules that catch the same instance via different discriminators (the comsvcs case: CallTrace vs StartModule — same set, not real synonyms). Recording why each instance fired (ground_lattice.why() already half-computes it) turns the set into a profile and resolves same-set / different-mechanism.
  • Cross-corpus ablation — the instance worry, operationalized. Run the treatment over N corpora and diff the result-CIDs (the manifest already supports it). What's stable across corpora is structure; what moves is the instance. That measures the exact thing the question is about, and says which extracted relations are portable.
  • Don't collapse the two verdict axes — Belnap (discrete knowledge) and confidence (continuous log-odds) are orthogonal; keeping both per node instead of one scalar is a resolution choice already in the design, worth holding as more detectors land.
The honest one — and it is NOT a construction. Behavioral resolution is capped by data structure, not machinery. Atomic-red-team captures are pure-attack: no benign population (can't resolve precision/FP), cross-channel-disjoint (can't resolve same-channel rule disagreement). That's the wall both the catch-set lane and the fan-out battery hit. You cannot construct your way past thin data — the next jump in behavioral resolution needs differently-shaped data (benign background + same-channel variation; bots-v3 is the candidate), not more parsing of isolated captures.
One line. Resolution rises claim → structure → behavior across five axes. The structural half is portable (corpus-free); only the behavioral half is the instance (data-bound). So machinery alone sharpens the structural half (content_digest, no data needed) — the behavioral half moves only with better-shaped data (cross-corpus ablation quantifies it; bots-v3 is the first test of the cap).

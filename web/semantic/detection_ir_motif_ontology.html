Detection IR — a motif ontology with verified emitters

The relation is the invariant. The language is a phrasebook. The port is fidelity-attested.

canon · design · 2026-06-18 · molecule = a bonded gadget · emitter = a per-language phrasebook

A throwaway finder — walk the events, grab the EID1 whose command line contains comsvcs, join it to the EID10 lsass read on ProcessGuid — was written to locate a labeled instance, then discarded. Two objections, both correct, open the whole design: (1) discarding the selector violates canon's own thesis, and (2) the language it was written in is incidental — the relation is the invariant. (2) is the seam: detection logic wants an intermediate representation that is the relation, with a per-language emitter on each side.

The irony. _comsvcs_positive() is how the label "this EID10 is the malicious read" was produced. warrant-is-relational says trustworthiness lives in the derivation, not the result — so the selector's source belongs in the provenance DAG as the prov:Activity that derived the positive entity. Discard it and "how did you know?" has no content-addressed answer. canon opened the exact hole it exists to close.

1 · The unit is a molecule, not an atom

The right granularity is a recurring composite, not a single AST node.

GranularityProblem
atom — field == value the IR is just an AST with no semantic content; you re-implemented a parser and gained nothing.
whole rule nothing is reusable — you cannot share spawn→access across the twelve rules that use it.
molecule — spawn ⋈ access on ProcessGuid a small bonded gadget with detection meaning. The reusable, queryable unit.

The H2O analogy is exact: the bond is the point. The join key is what gives spawn ⋈ access emergent detection-semantics that field-equals and EID-filter do not have alone — just as H2O's polarity is absent from H and O. An atom is an operator with no detection meaning; a molecule is the bonded gadget that has one.

These molecules already exist in canon, un-named as such. The primitive families are the catalog — fanout (entity→distribution), coordination/MI (two streams→dependence), subgraph MotifSpec (multi-EID join), field-match (sigma_eval). Atlas is meant to be exactly this library. The IR is not new construction — it gives the primitives canon already has a queryable RDF surface + emitters.

2 · RDF is the IR; the molecule is a symbol; the language is a phrasebook

A detection is a graph of molecule-symbols (RDF, content-addressed). Each target language has an emitter mapping symbols → that language's code. Not a novel architecture — a proven one.

The strong precedent — OpenMath / OMDoc / MMT (canon's own mathabc thread). Content dictionaries are a content-addressed ontology of operations; an OpenMath object is a graph of those symbols; every CAS has a phrasebook translating symbols → that system's code. That is precisely "a code-symbol ontology that translates to any language" — already built for mathematics. The detection-IR is OpenMath phrasebooks for detection operations.

Same family, different domain: pySigma backends (Sigma AST → Splunk/KQL), CodeQL (code as a relational IR queried in one language over many), Semgrep (one pattern across languages via a common AST), MITRE CAR (pseudocode → Splunk/EQL/Sigma). The molecule ontology is the content-dictionary layer; the emitters are the phrasebooks.

3 · "Trivially translate to any language" is the part to delete

Structure ports trivially — the graph is just data. Semantics do not. This is exactly where OpenMath phrasebooks are real work, not a free lunch:

Rust  ends_with        (byte semantics)        ≠  Python .lower().endswith()  (Unicode casefold)
SPL   eventstats        (streaming window)      ≠  pandas groupby              (materialized)
+ null handling · case-insensitivity · timezone & ordering in the temporal join

The honest version: the RDF makes the structure language-agnostic; each emitter still needs per-target semantic care and a check that the emit preserves meaning. That check is canon's own machinery, eating its own tail:

motif-IR  →  emit to language X  →  ATTEST the emit's fidelity vs a labeled corpus  →  warranted port
Does the Rust emit cover the same labeled instances as the Python emit? That is exactly attest_fidelity — Belnap coverage of an artifact against ground truth. So the claim is not "trivial translation" but verified translation: language-agnosticism becomes a fidelity-attested property, not an assumed one. The only words to strike are "trivially / for free."

4 · Sigma→RDF ingestion is the first emitter pair, not a separate project

The coverage map and the SPARQL-vs-code split both wanted a Sigma→RDF ingestion. In this frame it is a special case of the IR:

  • A Sigma rule parses into a motif graph — selection/filter blocks become field-match and suppression molecules; a correlation rule becomes a join molecule.
  • sigma_eval (interpreter) and pySigma (compiler) become two emitters from the same graph, not two independent implementations of "what the rule means." Their agreement on a corpus is a fidelity check between emitters (§3).
  • Once rules are in RDF, the knowledge-layer questions become SPARQL — "which evaluable process_access rules claim T1003.001," the coverage/adjacency map, FCA/SKOS dedup of synonyms — instead of bespoke Python globbing YAML. Per-event firing stays code (the hot path); only the knowledge queries move onto the graph.

So the ingestion is the IR's proof-of-concept: one molecule vocabulary (field-match + suppression), two emitters, one fidelity check between them, one SPARQL knowledge surface.

6 · Honest scope — what this is not

  • Not a universal transpiler. Cross-language semantic equivalence is undecidable in general; the IR buys structural portability + a verification harness (fidelity), not guaranteed equivalence.
  • Does not subsume the hot path into SPARQL (§4) — firing stays code. The SPARQL emitter is a correctness oracle + the knowledge-query surface, not the firing path. Measured: the built eval_sparql ran the OTRF agreement check in 368s → 11s (parsing the ASK once), still ~1–2 orders slower than the Python predicate — per-event SPARQL means allocate a graph → insert triples → invoke a general planner for one boolean. Intrinsic, not a tuning bug; on billions of events SPARQL lags fatally. So the tiers are literal: hot path = the emitted predicate (Python now, Rust later, attested-equivalent); cold path = SPARQL over the rule graph — small, rarely-changing, hence precomputable/cacheable — and even there "SPARQL lags" is really "rdflib lags": a real triple store (Oxigraph, Jena, Neptune, QLever) runs the same SPARQL competitively. The agreement attestation (§3) licenses running the fast emitter in place of the oracle.
  • The molecule vocabulary is earned, not designed up front. Extract a molecule only when ≥2 real detections share it (concrete-first, the Binding discipline). A speculative ontology of unused motifs is the failure mode to avoid.
  • "Any language" is per-emitter work, each emitter fidelity-gated before it is trusted (§3).

7 · Smallest first slice

1. molecule dataclass + tiny RDF serialization for TWO molecules: field-match, suppression
2. parse the comsvcs Sigma rule into that motif graph                         (the ingestion)
3. two emitters: sigma_eval-shaped Python  +  a SPARQL ASK/SELECT over the graph
4. ATTEST the two emitters against each other on OTRF — they must agree (Belnap true)
   on every labeled event, else the IR is lossy and the diff localizes where
5. content-address the motif graph + record _comsvcs_positive as a prov:Activity
   in the verdict's provenance — closing the §0 hole

Do not build the Rust emitter, the full ontology, or correlation molecules first — layers 2+. The first slice proves one thing: one detection, two emitters, agreement attested.

One line. The relation is the invariant; the language is a phrasebook; the port is fidelity-attested — so "language-agnostic" stops being a wish and becomes a measured property, by the same machinery that warrants every other canon claim.

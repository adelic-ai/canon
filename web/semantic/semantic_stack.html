The knowledge stack

RDF to reasoners — what each layer is, why canon code-joins instead of reasoning, how that's really a compiler, and where the LLM actually sits (not where you'd guess).

canon · session synthesis · 2026-06-17 · triples → vocab → cartography → events → rules → record · abduction proposes, deduction verifies

A long thread untangling the graph zoo. The throughline: state knowledge declaratively at the top, compile it to a fast path at the edge, and keep the one creative-but-unsound component — the LLM — on the untrusted side of a verification boundary.

1 · The layers, each in one line

RDF
The graph substrate — triples (subject · predicate · object). How everything fits together; the space itself. Turtle/JSON-LD/N-Triples are just notations for it.
RDFS
Lightweight vocabulary — classes, properties, subClassOf, domain/range. Naming + a hierarchy, no heavy logic.
OWL
Vocabulary + logic — description logic (restrictions, disjointness, transitivity, inverses) so a reasoner can entail new facts. You reach for it only when you want inference.
ATT&CK / D3FEND
The cartography — the (revisable) map of the attack/defense space drawn in that vocabulary. The kinds of moves, not what happened. "As we know it now" = a hypothesis layer, not bedrock. D3FEND ships as OWL; ATT&CK as STIX/JSON.
OCSF
The vocabulary for the events that fill the map — a T-Box for telemetry at the RDFS level (typed classes + hierarchy, no reasoning). Ships as JSON Schema. The normalized "what happened."
Sigma
A predicate over events, pointing at the cartography — `selection` is a boolean over fields; `tags` link to a technique.
PROV-O + tiers
The record and the honesty — the per-result justification graph plus the guarantee tier. Canon's own layer; nothing above provides it.

Two distinct spaces, both schema-level: ATT&CK/D3FEND is the T-Box of attack knowledge; OCSF is the T-Box of events. A Sigma rule is a predicate over the OCSF A-Box pointing at the ATT&CK T-Box. And the same (actor, action, object) skeleton runs through all of it — a triple, an OCSF event, and a PROV-O activity are the same shape at different layers.

2 · Honesty is not accuracy — it's the refusal of false precision

Accuracy = the claim is correct. Honesty = the claim never exceeds its evidence. They're independent: a system can be honest but wrong ("can't tell → well_formed only", and it misses a real attack) or accurate but dishonest (right 99% of the time, confidently wrong on the 1%, no way to tell which).

The sharper contrast is precision, not accuracy. The signature dishonest move is false precision — reporting a crisp TRUE/FALSE when the evidence licenses only NONE or a partial answer. Inflating "unknown" into "no" is a precision claim the data doesn't back. Canon's NONE/BOTH values and tier demotions are the machinery for being honestly imprecise: a deliberately less-sharp answer instead of a falsely-sharp one. Canon optimizes honesty because honesty is checkable and accuracy usually isn't — there's no ground truth in the wild, but you can always verify a claim is backed by its inputs.

3 · Where OWL's reasoning lives, and what the reasoners do

The logic isn't a bolted-on engine — it's axioms in the .ttl that imply facts beyond what's stated. In D3FEND: a subclass taxonomy of digital artifacts; property restrictions ("a technique that accesses some Credential"); inverses linking offensive↔defensive through the shared artifact, subclass-aware. The reasoning is latent until something materializes it.

That something is a reasoner: it takes the axioms (+ optionally data) and computes what follows — classify (the full inferred hierarchy), check consistency, realize (which classes each individual belongs to), subsumption. The names:

DL reasoners      HermiT · Pellet (Openllet) · FaCT++ · Konclude · ELK (fast, OWL 2 EL profile)
rule / OWL-RL      Apache Jena · RDFox · GraphDB · Stardog   (materialize via rules over a triplestore)
Canon currently runs none of these. bridge.py code-joins by technique-id — it does the subclass-aware D3FEND derivation in Python instead of running HermiT/ELK over the ontology. A reasoner is what you'd add only if you went graph-join.

4 · Code-join vs graph-join is really a compiler

The graph/reasoner is genuinely beautiful: it's declarative. State the ontologies and a few relations once, and the cross-links fall out as entailments — add a framework, no new join code. But it can't be on the hot path: reasoners are slow (worst-case exponential), their entailments are opaque (a justification system would then have to justify the reasoner too), and 99% of the runtime need is a single keyed lookup.

The resolution is compilation — and it's the trajectory. The reasoner/graph lives at the cold layer (extend / build): it runs the slow declarative reasoning once, on demand, and materializes the result into the fast lookup the hot path code-joins over. Declare + reason (slow, rare) → compile to fast tables → execute (fast, always). The architecture calls it tiered compilation. You don't trade structural beauty for speed — the abstraction compiles to speed, the way a compiler turns elegant high-level source into fast machine code and you keep both.

So the code-join is the compiled output; the graph is the source you'd compile it from. Canon just hand-writes the fast table today (bridge.py) instead of deriving it from the ontology. The trajectory: make adding a framework "state the vocabulary," not "write more join code."

5 · Where the ML actually fits — not the compiler you'd guess

Tempting to call the ML "the compiler" (LLMs do turn fuzzy intent into structure). But in canon there are two compilers, split by epistemic type:

the reasoner — deduction, TRUSTED
Declarative axioms → materialized fast facts. Its entailments are sound — provably follow. This is the compiler you trust. Not ML.
the LLM — abduction, UNTRUSTED
Translates the fuzzy/unstructured — a new framework's docs, a raw-field→OCSF mapping, a candidate hypothesis — into candidate structured statements. Compiler-like, but its output is a guess.
Canon keeps the LLM on the untrusted side of a verification boundary: the LLM proposes, the deductive layer (reasoner / SHACL / the folds) verifies and compiles. It's "LLM proposes, canon verifies" applied to the knowledge layer — the LLM finds the witness (creative, expensive), the deductive compiler checks it (cheap, sound). Putting the LLM in the trusted-compiler seat is exactly the asserted-not-earned trap canon exists to refuse.

So the LLM handles where the fuzziness genuinely lives — semantic mapping, the SKOS-graded edges, "is this close enough" judgments — and the deductive compiler handles where soundness is required — entailment, validation, the tier. Abduction proposes; deduction disposes. That division is the whole point: it's how you get the LLM's reach without inheriting its overconfidence.

6 · Warrant is relational — the bottom line

Entailment, exactly: Γ ⊨ φ means φ is true in every model of the premises Γ — truth-preservation across all worlds, "cannot be otherwise given the premises." A reasoner is trusted because it is sound (emits only entailments), complete (emits all), and decidable (halts) for its logic — the trust lives in that proof, not in the machine. But soundness preserves truth from the premises; it does not establish them. Sound reasoning over false axioms is valid garbage. So the reasoner is trusted for the inference, never the inputs — and the framework's axioms are a human-authored, revisable map.

So "lemma or hypothesis" is a property of the derivation, not the statement. ATT&CK/D3FEND is epistemically stratified: definitional (true by meaning) and mechanistic ("to dump LSASS you read its memory" — a lemma relative to the Windows spec, conditional on a revisable platform: Credential Guard refutes the premise) are near-bedrock; only taxonomy / empirical / coverage are the hypothesis. The same sentence is a lemma relative to one premise set and a hypothesis relative to another. And a reasoner's conclusion inherits the epistemic grade of its weakest axiom — sound, but only as grounded as the shakiest premise it leans on.

Two relativities make the point precise: accuracy is relative to the premises (`Γ ⊨ φ` = true where Γ holds; change the premise, φ flips); warrantable precision is relative to the mode of backing (entailment = exact-relative-to-Γ; empirical = graded; a guess = none). Same statement, different backing, different status.

The thesis, in one line: trustworthiness is a property of the derivation, not the result. `anomaly = true` has no determinate epistemic status alone — a machine_checked-backed one and a guessed one are the same string and not the same claim. So warrant must travel fused with the result, unfakeable: a canon verdict is the statement + its provenance graph + its tier, welded so the warrant can't be stripped off or forged. A result without its derivation has no determinate status at all — which is exactly why the provenance DAG is the same object as the result, not a side-log. Everything above is the scaffolding; this is the load it carries. (design/warrant_is_relational.md.)

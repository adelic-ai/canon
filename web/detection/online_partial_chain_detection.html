Online partial-chain detection — the third stateful shape

The value is in the chain that hasn't finished. Catching a prefix needs a state shape that neither the per-event verifier nor the windowed surfacer provides.

canon · design · 2026-06-25 · partial-match shadows · recursive filters with forgetting · the identity graph

A completed kill-chain is a failure: by the time the full path to a crown jewel has materialized, the jewel is gone. So the thing worth detecting is the partial chain — the prefix, mid-assembly. That sounds like a small change to the chain checker, but it isn't: firing on prefixes changes what you persist. The object is no longer the path, it is per-entity partial-match state — the half-assembled shadow of an attacker, kept alive across time so a later fragment can join it. This note is the state shape that makes that tractable, and where it sits relative to what's already designed.

1 · Three online shapes, not two

Live stream ingest splits "detect live" along the verifier/surfacer axis and gets two shapes. A multi-stage kill-chain falls through the gap between them:

ShapeStateCatchesMisses
per-event verifier
Sigma round		 none a single event matching a rule anything spanning more than one event
windowed surfacer
the battery		 trailing window rarity of one feature against a population an ordered, multi-stage structure across identities
partial-match accumulator
this note		 sparse per-entity shadows a kill-chain prefix as it assembles, before completion (the hard parts — §5)
The chain checker is the forensic corner of the third shape. detection/chain.py recognizes complete chains in batch — "did this whole path happen." That is the right tool for after-the-fact investigation and the wrong one for monitoring. Monitoring wants the same chain logic run online over prefixes with state that survives between fragments. Same spec; opposite end of the completeness×abnormality space from the entity-path note — there the boolean complete chain was the completeness=full corner; here we live in the interior.

2 · "We throw the artifacts away" — the bug, named

A windowed or per-event detector is memoryless across its boundary: a fragment that doesn't complete a chain inside the window is discarded. But the fragments of a real intrusion arrive minutes-to-months apart and across several identities. Discarding the lonely fragment is exactly the failure — the prefix was the early-warning signal and we dropped it. The fix is not a smarter recognizer; it is to keep the fragment, attached to the entity, with decay, so the next compatible fragment can find it.

3 · Why this is not the intractable thing it looks like

"Maintain a belief over hidden attack-states for every entity" is a dense HMM, and it is intractable — worse than per-entity, because attacks couple identities (the kerberoast pivot binds the roasting account and the cracked service account), so the honest hidden state is over sets of identities: exponential. You don't pay that, because of sparsity:

  • Instantiate on first light. ~all entities are in the null state showing nothing; you never allocate a shadow for them. A shadow is created only when an entity produces a fragment worth keeping.
  • Decay and prune. Each shadow loses weight with age and is dropped when it falls below threshold. The live set is small — the handful of entities currently mid-something — not the whole population.
  • HMM is the semantics; partial-match is the implementation. The probabilistic model (hidden attacker state, transition likelihoods, the completeness×abnormality score) rides on top of a complex-event-processing partial-match store: maintain open prefixes, advance them as events arrive, expire on timeout. You run the expensive inference over the live shadows only — Viterbi over five, not a million.

4 · The comp­actness is one operator — recursive filters with forgetting

Three things in this architecture decay over time, and they are the same operator new = α·obs + (1−α)·old wearing three different carriers:

LayerCarrierForgetting meansHome in canon
baseline (EWMA)a level — normal-for-this-entity old normal stops counting → tracks drift baselines / battery change-detection
shadow decaya hypothesis weight — "may be mid-chain" stale suspicion stops counting → bounds prefix lifetime new — this note
belief (HMM forward)a distribution over hidden states falls out of the transition dynamics the killchain/HMM machinery
Structurally and abstractly the same; conceptually distinct. EWMA is the point-estimate member of a family — steady-state Kalman / RLS-with-forgetting; the HMM forward step is the same recurrence one richness level up (a distribution, not a point). That shared skeleton is the answer to "the log as a weird, compact database": you never replay history, you keep a recursive sufficient statistic — the current baseline level, the current live-shadow set, the current belief — and update it per event. Forgetting is what lets a bounded state stand in for an unbounded stream. Share the skeleton, keep the carriers' decay constants distinct — they run against different clocks (a baseline drifts over weeks; a hypothesis lives for an attack's dwell time).

5 · What the shadows live on — the identity graph as a data-plane IR

A shadow is a partial walk over a graph, so the state shape presupposes a graph. Its nodes and edges:

  • An action is a typed edge, not a bare predicate: Subject × Object → StateΔ — who acted, on what, what changed. Chains chain because the object of one action becomes the subject of the next: the object of "roast" (the service account behind the SPN) is the subject of the later "logon." A path is a sequence of typed edges where one's codomain feeds the next's domain — not a conjunction of independent truths.
  • The attacker is a hidden entity that wears identities. Only a security principal acts at the authorization layer (a process runs under a token = an identity), but the thing you're tracking — the campaign — puppets several identities and pivots between them. The identity is the observable; the attacker is the hidden state. This is what couples shadows across identities. Granularity varies with telemetry: process, identity, or asset.
  • This graph is a data-plane IR — a different frontend axis than the IR spine describes. There the frontends are rule languages (Sigma/CAR) lowering to the detection-IR; here the frontends are telemetry sources (eslogger, Sysmon, ETW, CamFlow PROV) lowering to an observation graph. The eslogger→OCSF adapter is the first such frontend already; OCSF/SKOS is its vocabulary. Reuse PROV-O graph shape + OCSF vocab — mint the in-memory representation, not a fourth standard. A detection-IR motif (spawn ⋈ access on ProcessGuid) is then a query over this observation graph; the two IRs meet only because they share the entity vocabulary.
The provenance-aware-OS ideal, and what we actually own. Whole-system provenance (CamFlow, PASS) and streaming provenance-graph IDS (SLEUTH, HOLMES) emit the graph at the source instead of flattening it to a log and reconstructing it. That ideal relocates the hard parts rather than removing them (the kernel sees syscalls, not "TGS request, RC4"; the graph is the firehose; it's per-host). canon can't change a customer's OS — so its move is to consume a graph-at-source where one exists and reconstruct it from flat logs where it doesn't. The realizable slice is the producer canon owns: emit PROV-shaped typed edges from our own collectors. This is the ADJACENT band (source-custody/capture), not canon's core edge.

6 · Honest hard parts

  • Entity resolution is the actual open problem, and the partial-match store does not solve it — it needs the join key. The known-pivot cases stitch (kerberoast's SPN → service-account; pass-the-hash); the unknown-coupling case — an attacker using two identities with no observable link — stays an honest NONE. This is the cross-actor linkage rung; it is a relational join across identities (the attack-graph view), not a per-actor scan, and chain.py today is per-actor.
  • Prefix-firing has brutal FP pressure. Surface every 1-of-3 fragment and you drown. The only thing that makes partial surfacing survivable is the abnormality-for-this-entity gate — i.e. the EWMA baseline — and that is data-gated on the entity's history (the recurring wall; same data dependency the entity-path note flags).
  • The decay constant is adversarially attackable. Short → miss slow attacks (APT dwell is months; roast-then-logon can be weeks). Long → shadows pile up and false-join. "Low and slow" is precisely pacing under the forgetting factor. There is no clean constant; it is a recall/FP knob with the adversary's hand on it.
  • In-memory graph vs the durable journal — a real tension. Live ingest deliberately writes NDJSON to an append file with a checkpointed offset, so a restart is resume, not gap (custody). A pure in-memory observation graph trades that away. Resolution: the graph is derived hot state, replayable from the journal; the NDJSON stays the durable custody record. The graph is the analysis surface, not the system of record.
  • The IR's expressiveness is the detection ceiling. If the observation IR can't represent ticket encryption type, no frontend delivers RC4 and no shadow can see kerberoast — regardless of source. Designing the IR's vocabulary is designing what's detectable (the sub-atomic schema floor).

7 · Honest scope — built vs designed

  • Built: detection/chain.py (complete-chain, batch — the forensic corner); the eslogger→OCSF adapter (the first observation frontend); the battery (windowed surfacer); the fold substrate / computation DAG. The per-actor limitation and the complete-chain limitation are both real today.
  • Designed, not built: the partial-match accumulator as the third online shape; the sparse decaying shadow store; the recursive-filter triple sharing one operator; the observation-graph data-IR as a telemetry-frontend axis. None of this exists in code yet.
  • The seed (smallest real step): add a per-entity shadow accumulator to the (designed) reader loop — one decay constant, one EWMA baseline, the existing kerberoast spec run over prefixes — and show a prefix fires before completion on the faker corpus. Honest caveat: the faker can prove the mechanism (a prefix fires early, decays, false-joins under a bad constant) but cannot earn fidelity — author-both-sides circularity. Real validation is gated on real multi-stage telemetry, the same wall the kerberoast track hit.
One line. Between the per-event verifier and the windowed surfacer sits a third online shape — the per-entity partial-match accumulator — which fires on kill-chain prefixes by keeping sparse, decaying attacker shadows over an identity graph; it is tractable because the shadow, the baseline, and the belief are one recursive-filter-with-forgetting operator (compact sufficient statistics, not a replayed log), and it is honest because the cross-identity join, the FP gate, and the decay constant are named as data-gated or adversarial rather than assumed.

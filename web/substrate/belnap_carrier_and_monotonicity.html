The Belnap carrier & the ≤k-monotonicity invariant

What is genuinely proven, and where the claim is stronger than what the code checks.

canon · close reading · 2026-06-07 · contracts/carrier.md · packages/provenance/src/provenance/{carrier,monotone}.py · tests/{test_carrier,test_monotone,test_confidence}.py

Read the contract (contracts/carrier.md), the impl (packages/provenance/src/provenance/carrier.py), the gate (monotone.py), and the tests. Here's the actual structure, what's genuinely proven, and where the "every fold is ≤k-monotone, CI-checked" claim is stronger than what the code checks.

The one move that makes it mechanical: two independent bits

A Belnap value is a pair (t, f) — t = "some source told me true," f = "some source told me false," independent (carrier.py:40-54). The four values are just the four bit-combos:

NONE = (0,0)   TRUE = (1,0)   FALSE = (0,1)   BOTH = (1,1)

That independence is the whole trick. It means both orders and all operations are componentwise bit ops — no truth tables to memorize, no special cases:

  • leq_k = componentwise ≤ on (t,f) (carrier.py:83-85) — knowledge only grows as bits flip on.
  • kjoin (⊕, accumulate evidence) = componentwise OR. kmeet (⊗, consensus) = componentwise AND.
  • tjoin (∨, ∃-detect) = (t OR, f AND). tmeet (∧, ∀-validate) = (t AND, f OR).
  • neg (¬) = swap the pair.

TRUE ⊕ FALSE = (1,0)|(0,1) = (1,1) = BOTH: two disagreeing sources produce a contradiction, not an average. TRUE ⊗ FALSE = (1,0)&(0,1) = (0,0) = NONE: no consensus, no knowledge. Both fall straight out of the bit model — nothing is stipulated.

Two orders on one carrier — and the discipline of not mixing them

This is a bilattice: the same four values under two different partial orders.

  • knowledge ≤_k: NONE ≤ {TRUE,FALSE} ≤ BOTH — "how much is asserted."
  • truth ≤_t: FALSE ≤ {NONE,BOTH} ≤ TRUE — "how true," with t up and f down (carrier.py:88-90).

The code enforces the separation structurally: only ~ (negation) is an operator dunder; kjoin/kmeet/tjoin/tmeet are named functions, never overloaded (carrier.py:59-60), precisely because writing a & b and silently getting the wrong lattice's meet is the subtle bug the contract warns about (carrier.md:22-23). You cannot accidentally combine evidence in the truth order.

The deepest point: neg is ≤k-monotone (this is why Belnap, not Kleene)

Negation normally reverses order. Here ¬ swaps both components, which preserves componentwise ≤ — so ¬ is ≤_k-monotone (carrier.py:124-129), while being ≤_t-antitone as a negation should be. ¬NONE = NONE, ¬BOTH = BOTH; only TRUE/FALSE flip.

That property is load-bearing for the one hard seam in the whole system (architecture §6). Temporal negation — "C never occurred" = ¬(∃ C). Because ¬NONE = NONE, not knowing whether C happened propagates to not knowing whether ¬C holds, automatically. A 3-valued Kleene logic has only one order and can't carry both "silent" (NONE) and "contradicted" (BOTH) — it collapses to the SQL-NULL→FALSE bug the project exists to prevent. Belnap's two-order structure with monotone negation is the minimal algebra that doesn't.

Caveat, stated precisely: the algebra propagates honestly once the input is right, but it doesn't choose the input. "C-absent" must enter as FALSE when the feed is live and as NONE when the feed is silent — and that distinction is feed-liveness/custody, out-of-band from the algebra. The carrier makes the partiality discipline free; it does not make getting the feed-liveness call free. That's the "seam that isn't free."

The invariant, and how it's actually proven (the genuinely strong part)

Every fold is ≤_k-monotone: feeding a child more knowledge may only move the result up ≤_k, never down (carrier.md:88-97).

Because the carrier is finite (four values), this is not property-tested or sampled — it's checked exhaustively, which is a complete proof. monotone.py:21-47 enumerates: unary over all 4 values, binary over the full 4×4×4 product in each coordinate. test_carrier.py:163-170 runs that gate over all five operations (parametrized binary ops + neg) — so "all five ops are ≤_k-monotone" is a verified complete enumeration, not an inherited claim.

Two things here are better discipline than usual:

  • The gate is tested to catch a violation, not just pass the real ops: test_monotone.py:32-41 feeds it deliberately knowledge-losing maps (BOTH → NONE) and asserts it fails. A checker that only ever returns True is worthless; this one is shown to bite.
  • assert_k_monotone(..., arity=) (monotone.py:50-66) is the reusable CI form, so the acceptance test "add concern N without touching concern M" really is reduced to a decidable, complete check — for the carrier algebra.

Where the claim outruns the check (the honest boundary)

"Complete proof, not a sample" is true for the carrier-internal ops. It is not automatically true for the concrete folds, and the difference matters:

A real fold (confidence) outputs over LogOdds | None — an infinite domain. The exhaustive gate only types Four → Four. The resolution in the code is the two-axes factoring (carrier.md:130-133, test_confidence.py:47,84): a Confidence carries a belnap field (a Four) separately from the graded probability. The ≤_k invariant binds only the Four knowledge-projection; the LogOdds is the orthogonal graded axis and is deliberately not subject to ≤_k. So the system never tries to make ℝ a lattice — it splits every fold's output into (a four-valued knowledge field that obeys the complete-proof invariant) + (whatever typed payload).

The consequence to keep honest: each concrete fold's monotonicity over its actual infinite input domain is established by example tests, not exhaustion — e.g. test_confidence.py:115-122 checks one transition (NONE → TRUE moves the join up). That's a spot-check, not the complete enumeration the carrier ops get. Precise statement: the algebra is exhaustively proven monotone; the individual folds are example-gated. The marketing line "the universal invariant is CI-checkable" conflates the two — the carrier half is a theorem, the per-fold half is a sample.

And the invariant is a safety property, not a correctness one. ≤_k-monotonicity guarantees a fold never silently loses knowledge (NONE never becomes FALSE behind your back). It says nothing about whether the value computed is right. A fold can be perfectly monotone and compute garbage. The carrier guarantees honest partiality; it does not guarantee a good detector — which is exactly the distinction Gemini's review flattened.

Appendix — the V4 / sign-group observation (added 2026-06-07)

Not part of the original delve; appended because the algebraic coincidence is worth pinning down precisely.

The carrier set {NONE, TRUE, FALSE, BOTH} under componentwise XOR is exactly the Klein four-group V₄ ≅ ℤ₂ × ℤ₂, with NONE = (0,0) the identity and every other element its own inverse (order 2). Equivalently, write each bit as a sign in {+1, −1} and the carrier is {±1}² under componentwise multiplication — the "sign group," which is V₄. So yes: as a set with that group law, Belnap's carrier is V₄ itself — not a proper subgroup. (V₄'s proper subgroups are its three ℤ₂'s and the trivial group; the carrier is the whole group.)

But the group law is not the algebra canon runs on. XOR appears in none of the four Belnap operations. The ops canon actually computes with are the bilattice meet/joins (componentwise OR and AND) plus the swap-negation — order-theoretic structure, not the group operation. V₄ is the carrier's set-level symmetry; the bilattice is a different object layered on the same four points. The "square" you're seeing is real but it's the Hasse diamond of ≤_k (NONE at bottom, BOTH at top, TRUE/FALSE incomparable in the middle = the Boolean lattice 2²), which happens to draw the same square as V₄'s Cayley graph.

One place the group view does touch the algebra: negation. neg(t,f) = (f,t) is a linear map over ℤ₂ (the permutation matrix swapping the two factors), so it is the nontrivial automorphism of V₄ that exchanges its two ℤ₂ generators — and as a permutation of the four points it's the transposition fixing NONE/BOTH and swapping TRUE/FALSE, generating an order-2 subgroup of Aut(V₄). That is the one spot where "Belnap ≅ V₄" and "canon's actual operations" coincide rather than merely co-locate. Everywhere else, the group structure is a true but inert isomorphism: nice to know the carrier is V₄, but the monotonicity story lives entirely in the two lattice orders, which XOR has nothing to say about.

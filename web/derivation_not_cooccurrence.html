Derivation, not co-occurrence

Things don't co-occur on a machine — they're derived from a root. Taint is what flows along the derivation; absence reads opposite ways depending on direction.

canon · design conversation · 2026-06-12 · the frame under all five detection cells

"Co-occurrence" — two events sharing a node — is a convenient lie. On a machine nothing merely co-occurs; everything is caused. Two events sharing a ProcessGuid aren't co-occurring, they're both derived from the same process-creation. The honest primitive is wasDerivedFrom, and it has a root.

Everything roots in a derivation root

The host's causal backbone is the process tree: EID1 (process create) + ParentProcessGuid edges, every action — file, registry, network, an lsass read — performed by a process an EID1 created, chaining back toward boot. So "join at a node" is really shared derivation, and the process tree is the spine everything hangs off.

Rootless events don't exist. Events that don't root in a host EID1 — a Kerberos 4769, a network flow, a cloud API call — still have a natural process root (lsass / the KDC on the DC; the socket-owning process; an API identity), or a collection of legitimate roots they could derive from. That root may live on another machine or be uncaptured (→ NONE, a truncated chain) — but it exists. So EID1 is the host instance of a universal idea: every domain has a derivation root (host = process tree; auth = session/KDC; network = socket; agent = the trace / the user turn). The security question is the same in all of them.

Absence is asymmetric on the derivation axis

A missing edge means opposite things depending on which way you walk — and this is the load-bearing correction to naive entailment.

backward — missing ANCESTOR = strong

An orphan: a present event whose required ancestor is absent. This is structural / a precondition — near-logical necessity. A 4769 (service ticket) cannot legitimately exist without a 4768 (TGT); a 4769 with empty wasDerivedFrom is a forged TGT (Golden Ticket). The general-purpose tool.

forward — missing DESCENDANT = weak

A gap: a present event whose expected follow-on never came. This is statistical, not structural — and usually benign. You authenticated (4768) and went to get coffee; no service request (4769) is completely normal. A special-case tool.

Why forward is weak: it's a distribution over nexts × time, not an entailment

An anchor doesn't entail one necessary next. It induces a transition distribution — a collection of possible nexts, each over a typical time window, and crucially one branch is always "benign terminal / nothing happens."

BACKWARD (orphan)   P(4768 exists | legit 4769) = 1          → necessity. absence = forgery.   STRONG
FORWARD  (gap)      P(next | 4768) = { logoff 0.5, 4769·svc-A 0.2, 4769·svc-B 0.1,
                                       …, NOTHING 0.15 }  over minutes  → a distribution.  WEAK

So a missing descendant is anomalous only when all three hold: the next-distribution is narrow (few legitimate nexts), the typical time window has elapsed, and the benign-terminal branch is implausible here. The comsvcs case is the rare degenerate distribution — P(lsass-read | comsvcs MiniDump spawn) ≈ 1, no benign-terminal branch — which is the only reason forward-entailment fired cleanly there. That's the exception. Forward is statistical (transition × timing); backward is structural (a precondition). Which is why the orphan is the robust general detector and the forward-gap is the narrow special case.

Even the orphan needs the observability gate. A real 4769 with no local 4768 also has benign causes — the TGT came from another DC, or before the window. So the check is "derives from none of the set of legitimate ancestors," and "genuinely forged" vs "ancestor-exists-but-unobserved" is the same completeness call as everywhere else.

Taint is what flows along derivation

Once derivation is the primitive, the security question is one shape in every domain:

between the trusted root and a dangerous action, did untrusted material enter the derivation chain?

Exfiltration = a wasDerivedFrom path from a secret node to an external sink. Untrusted-to-action = a path from an untrusted source to a privileged action. These are the competition's predicates, and they are taint-flow queries over the provenance graph — not input validation. Detection is flow-side and intent-agnostic.

Indirect input: any material, and intent collapses at detection

The untrusted material is anything the LLM ingests that didn't come from the trusted operator — a tool result, a web page, an email, a file, a retrieved doc, another agent's output. The model has no reliable boundary between data-to-process and instructions-to-follow; it's all tokens. A hidden "gesture" that is an intentional injection and one that is accidental (instruction-shaped prose) look identical to the model. So you cannot detect by classifying the input's intent — you watch the flow / effect. Accidental and intentional both produce the same taint-flow and are equally dangerous at a sink; intent is for attribution and response, not detection.

So is it a "smart firewall"?

Partly — and the split matters. A firewall prevents at a boundary; that describes the guardrail (a taint-aware action gate that blocks the dangerous tool call — "smart" because the danger is contextual, the data is tainted, not the verb). Canon is the other half: accountable detection over the trace — a justified judgment on each action carrying its provenance, less block/allow and more "here is why this is or isn't safe." They compose: canon's flow-detection is what makes the gate smart, and the verdict is why it acted.

The single frame under all five cells. Co-occurrence was the convenient lie; derivation from a root is the truth, and taint flows along it. Backward-absence = a missing precondition (strong); forward-absence = a thinned transition distribution (weak); a tainted path from untrusted to a sink = the attack. Same graph, one primitive, every domain — host detection and the agent-security competition both.

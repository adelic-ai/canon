The W's as a coordinate system

Framework = the axes. Graph = the points. Detection = a region.

canon · the unifying lens · 2026-06-06 · who · what · when · where · how

A node in the provenance graph already carries who / what / when / where / how as its edges. So the W-record is not something a detector emits — it is the coordinates of an event in a multi-dimensional space. Once you see the W's as coordinates, detection, routing, correlation, and the verdict all become operations on one indexed space.

The W's are the coordinates of each event

who   = the Agent        (prov:wasAssociatedWith)      — a user / principal
what  = the Entity       (prov:used / wasGeneratedBy)   — a binary (by hash), file, resource
when  = startedAtTime                                   — event-time
where = host / data-component                           — the layer (host / net / cloud / auth)
how   = command / params                                — the action taken

An event is located at (who, what, when, where, how). Slice by fixing some and varying the rest — [who=pupy.godoy, :, :, :, :] is "everything that account did." Route by a partial coordinate — fix what/how, retrieve the techniques that apply there. Correlate by shared coordinates — same who across events is the same point on the who-axis.

Three precisions that make the lens correct

PrecisionConsequence
categorical keys, not numeric positions it's a dictionary / graph, not a tensor — no native distance between who=A and who=B. Resolves tensor-vs-graph: sparse + categorical → don't densify.
coordinates can be NONE a partially-addressed space — who=known but where=unobserved. The address itself carries honest gaps.
each axis is a structured ontology what ∈ process-tree, who ∈ AD/IAM, where ∈ ATT&CK/OSI layers — you query by walking axis-ontologies (why RDF/SKOS), not by exact key match.

The same coordinate, reached from the raw event

The lens above arrives top-down, from the framework. It also arrives bottom-up, from the raw log — and getting there sharpens two of the precisions. A Sysmon EventID=1 record is a named tuple — {Image, CommandLine, ProcessId, User, ParentImage, Hashes, UtcTime, …}. Each field is an axis, its value is the position on that axis, the record is the coordinate. The same point as the W-record, located from the data side instead of the framework side. (added 2026-06-11)

1 · The value is a position within an axis-ontology — so distance is subsumption, not arithmetic. what = KerberosTicket is near Credential because KerberosTicket ⊑ Credential (one subClassOf+ hop). Nearness on the what-axis is a walk through the artifact taxonomy, not |a − b|. This is what the "axes are structured ontologies" precision buys: the categorical-keys precision said there is no numeric distance — the axis-ontology gives you a structural one in its place.

2 · A record locates a neighborhood, not a single point. One EventID=1 names several individuals at once — the process, its parent, the user, the binary. So it doesn't drop one dot; it pins a small subgraph (process —wasInformedBy→ parent, —wasAssociatedWith→ user, —used→ binary). That is the deeper reason the space is a graph and not a tensor row: the "coordinate" is the coordinate of a region.

And the bottom-up view makes the role of normalization exact — it is a change of axes:

Sysmon EventID=1   =  a coordinate in the SOURCE-NATIVE axes  (~20 Sysmon fields)
   │  project onto the canonical axes
W-record           =  the same point on the 5 shared axes      (who / what / when / where / how)
   │  re-express in a shared vocabulary
OCSF / CASE-UCO    =  the coordinate in axes EVERY source shares → cross-source comparable

So "what does normalization buy," in coordinate terms: it re-expresses each source's native coordinate in shared axes, so a Sysmon point and a CloudTrail point live in one space — and the content hash makes same entity across sources = same coordinate, structurally rather than by fuzzy match. The artifact type (d3f:Process) is itself the value on the "what-kind" axis; PROV edges are the neighborhood's structure.

The unification. If the W's are coordinates, then the framework is the coordinate system. 
framework (semantic-cyber / OCSF / CASE-UCO)  =  the AXES + their structure
provenance graph                              =  the POINTS plotted in it
detection                                     =  an anomalous REGION
routing (W→route)                             =  a partial-coordinate LOOKUP
verdict                                       =  a fully-addressed point + carrier values
The framework stops being "a verifier library beside the work" and becomes the space the work happens in.

W→route, after the reshape

W→route was discovered through the IT/DT battery, but the W's were never the battery's — they are native to the graph. So W→route is really the graph ↔ framework join, keyed on any flagged node's coordinates. The battery is one flagger among many (a framework signature firing, a milestone hit, a human pick); routing is uniform over any flagged node, which makes the bidirectional entry trivial.

The alignment problem relocates (not dissolves). Old: route-time fuzzy mapping from canon's vocabulary (entity=IP) to framework terms — the open research problem. New: the ingest-time un-flatten (SKOS → OCSF → CASE-UCO) assigns framework-aligned coordinates up front, so routing is a lookup in already-aligned terms. The alignment becomes a bounded, per-source, do-once bridge at ingest instead of an open per-query inference. Better place for it — though the bridge quality is now load-bearing (itself a fidelity-attestation target).

canonmon = one shared coordinate system

The multi-source unifier's whole job, in these terms: put every source in the same W-coordinate system. The un-flatten assigns comparable coordinates across host / network / cloud / auth; the content hash (CID) is identity along the who/what axes; same entity across sources = same coordinate. Cross-layer correlation is just "events at the same coordinates," and lateral movement is a path through coordinate space.

It's a lens, not the implementation. The real objects are the graph + framework + folds. The one thing not to take from the coordinate picture is "so build a tensor" — the categorical-keys + sparsity precisions say dictionary / graph, never a dense array.

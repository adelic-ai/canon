Schema impedance as a SKOS-graded, justified mapping

Cross-platform type correspondence is "very close but no guarantee." Represent the closeness honestly — graded, justified, contestable — instead of flattening it to equality.

canon · session synthesis · 2026-06-16 · impedance → SKOS grade → justified/callable → load-bearing demotion → contested commons

A detection written against one platform's schema silently fails against another's, even when the underlying event is identical, because the two name or encode the same fact differently. The fix is not to pretend the schemas are equal — it is to model the mapping as a graded relation that carries its own reasons, let the grade affect a verdict only where it is load-bearing, and keep the whole thing contestable.

Terms, tersely.
impedance
Two schemas describe the same fact with different field names or value encodings, so a rule matching one silently misses the other. Borrowed from signal engineering: connected, but nothing transfers.
SKOS
Simple Knowledge Organization System — a W3C vocabulary for relating concepts across schemes, with graded mapping relations (below).
exactMatch
The two concepts are equivalent; interchangeable with confidence. = agreement.
closeMatch
Similar enough to swap in some applications, explicitly NOT equivalent. The "close but no guarantee" case.
broadMatch / narrowMatch
One concept is more general / more specific than the other. The hierarchical (position) axis.
support set
The fields/aspects a detection's predicate actually reads. A mismatch matters only if it lands here.
load-bearing
The differing dimension is in the rule's support set — the mismatch can change the outcome.
demote
Lower the verdict's earned guarantee tier, recorded and shown on demand. Never a silent change.
verdict
A DetectionVerdict instance; its .provenance is the CID into a PROV-O DAG holding every fact behind it.
Belnap BOTH
The four-valued logic's "conflict" value — agreement and credible dissent at once; a soundness flag, not a coin-flip.

1 · The problem: impedance

A SigmaHQ Kerberoasting rule keys on raw-Windows ServiceName / TicketEncryptionType. Our corpus (Splunk-CIM) carries the same 4769 RC4 ticket as Service_Name / Ticket_Encryption_Type. Same event, same attack — block_matches looks up ServiceName, finds nothing, the rule doesn't fire. A schema mismatch masquerading as a non-detection.

Two structural answers, complementary, both lossy:

OCSF      (data-side)  normalize each source INTO a common schema once; detect against OCSF
pySigma   (rule-side)  keep data native; transform the RULE per-schema (field-mapping pipelines)
Not the same as a model difference. Impedance is a naming/encoding mismatch a field-map fixes. The Rubeus EID-4611 logon artifact vs the behavioral 4769 fan-out is two different events — no field-map bridges that. Keep them separate.

2 · The formalism: a graded relation, not equality

Cross-scheme correspondence is a SKOS mapping relation. There are two gradings:

  • Tightness — exact / close / related. How safe it is to treat them as the same.
  • Position — broad / narrow. Which direction the mismatch goes (generalize vs specialize).

Canon already uses the position axis: the Sigma panel's FCA/SKOS dedup orders rules by broader/narrower field-sets ({TargetImage} is broader than {GrantedAccess, CallTrace}). This is the same lattice generalized from "which rule is broader" to "which platform's type is broader."

3 · The grade must be justified and callable — not a label

A SKOS grade you cannot justify back to its inputs is exactly the asserted-not-earned result canon refuses. So the mapping edge is itself a justified verdict — a fold over per-dimension difference leaves — and the instance answers "why this grade?" on demand.

@dataclass(frozen=True)
class DiffScore:
    dimension: str       # name | value-encoding | semantic-scope | osi-layer | cardinality | ...
    score: float         # contribution to the mismatch (0 = identical)
    source_defn: str     # pointer to THIS platform's definition of the concept
    target_defn: str     # pointer to the OTHER's definition

@dataclass(frozen=True)
class TypeMapping:
    source: str; target: str
    relation: str                    # exact | close | broad | narrow | related  (the SKOS bucket)
    subscores: tuple[DiffScore, ...] # what the grade folds over
    osi_layer:  int | None           # the coordinate-system view: WHERE the concept sits
    coordinate: tuple | None         # node coordinate in concept space
    neighbors:  tuple[str, ...]      # relative position to neighbors

    def magnitude(self) -> float: ...        # quantitative distance (vs the qualitative bucket)
    def why(self) -> "Justification": ...    # relation + subscores + definition pointers, shown on demand
    def is_load_bearing(self, support: set) -> bool: ...   # is the differing dimension in the rule's support?
    def demotes(self, tier, *, load_bearing: bool): ...    # gated effect — never a silent pass

The grade carries the reason (which dimension differs), the sub-scores, pointers to each platform's actual definition, and positional metadata — OSI/IP layer, a node coordinate, relative position to neighbors. SKOS gives the qualitative bucket; magnitude is a further layer — don't fake precision.

4 · Storage vs effect: the grade always exists; only its consequence is gated

Two things, never conflated.
  • Always stored: the grade + its reasons. Computed once, intrinsic to the edge, independent of any detection. Every grade points to its reasons, full stop.
  • Gated: the demotion consequence on a particular verdict. A closeMatch on a field a rule never reads is inert — no demotion.

So demotion is a join, and it needs both gates:

demote(verdict)  ⟺   (grade ≠ exactMatch)        # not agreement
                  ∧   (load-bearing)               # the differing dimension is in the rule's support set

Agreement kills the penalty; non-agreement on an unused field also kills it. You need disagreement the detection actually leans on. And inert ≠ unrecorded: the verdict still carries "field X is a closeMatch, here's why, but this detection doesn't use X → no demotion." The non-demotion is itself shown on demand.

"Takes effect" = a recorded tier demotion in the verdict's guarantee (mechanical, demotable). Surfacing a demoted verdict for analyst review is a downstream consequence, not the mechanism. The transparent per-dimension grade exists so the user (or an agent) can reason for themselves whether the difference is load-bearing on this detection — part mechanical (is the field in the support set?), part semantic (does 0x17 vs RC4-HMAC flip the predicate?).

[Future — examine closely] Three definitions, per event. Load-bearing above is stated syntactically — is the field in the support set? — but it is deeper: whether a difference bites is a function of three definitions meeting at the detection event — the source field def, the target field def, and the detection's own definition. The same edge-grade is load-bearing for one detection and inert for another, by what each asserts about the field (presence vs literal-equality vs numeric-compare; 0x17 vs RC4-HMAC is inert if only presence is tested, load-bearing if compared literally — and "which" is a fact about the detection's definition, not the field's). Because a Sigma rule is a fairly formal predicate, much of "does this difference matter to THIS detection" is computable from the rule's AST crossed with the dimension the edge differs on — shrinking the judgment residual.

5 · The verdict object — everything routes back to provenance

A detection result is a DetectionVerdict instance. Its .provenance is the root CID into a content-addressed PROV-O DAG; walking it (to_prov / lineage) recovers every fact — the W-record (who/what/when/where/how), the five folds (confidence, custody, guarantee, temporal, value), and the corroboration edges. Enough to almost mechanically render a report or a chart.

verdict (instance)
  └─ .provenance = CID ─▶ PROV-O DAG
        ├─ W-record:  who / what / when / where / how
        ├─ folds:     confidence · custody · guarantee · temporal · value
        ├─ corroboration edges:  sigma_corroboration → rule-class entities
        └─ mapping edges:        TypeMapping.why() → per-dimension diffs + definitions
Storage stance. On a Splunk-notable eval the verdict artifact is an ephemeral tmp file tagged with the notable id; retention is the customer's SIEM policy, not canon's. And it is reconstructable from the content-addressed inputs — re-derivable from the retained notable + the deterministic DAG. Don't reinvent storage. Gaps: the report/chart renderer and a persisted verdict store aren't built — the data model supports both trivially.

6 · The edges as a living, contested commons

A grade is not a one-time assignment — it is a contestable claim that accrues peer review over time, and the reviews are themselves canon-native verdicts. None of the machinery is new:

Dawid–Skene
EM that jointly estimates the true grade AND each reviewer's reliability from disagreeing labels. Reviewer-reliability-as-telemetry is the latent parameter it already recovers.
credibility theory (Bühlmann)
Actuarial per-entity reliability weighting — the per-entity baseline, pointed at reviewers. A reviewer's track record weights their next grade.
review = argument, not vote
Because the grade is justified, a review carries its reasons; weight by justification quality + track record, not raw count. Majority ≠ correct, especially for expert schema judgments.

Even agreement is contestable. An exactMatch is a claim with provenance, not a fact; an AI or human can contest it. A credible contestation doesn't silently flip the edge — it enters a recorded contested state (Belnap-BOTH-flavored: agreement + credible dissent = a soundness flag), cataloged and analyzed.

Layer split.
  • Core (canon): the edge is a justified, contestable verdict with provenance. Reviews and reviewer-reliability are just more verdicts — same machinery, recursive. Works with one reviewer, scales to a crowd unchanged.
  • Ecosystem (the "other business"): contribution / governance / attribution — opt-in, OSS, named-or-anonymous, recognition. Separable and undecided.
Don't hand-wave the failure modes. Reputation systems get gamed — collusion, sockpuppets, majority-tyranny, cold-start. Dawid–Skene + credibility-weighting down-weight bad raters but don't immunize; the justification-weighting (a graded argument is auditable, a vote isn't) is the real defense. Convergence is likely but not guaranteed — a persistently-contested edge is honest signal (genuine platform ambiguity), not noise to resolve away.

7 · The electrical-engineering analog

It goes past the borrowed word "impedance." The core analog is the reflection coefficient — and it lines up structurally, including the two-axis grading.

When a source and load impedance don't match, not all the signal transfers — some reflects. The reflection coefficient Γ = (Z_load − Z_source) / (Z_load + Z_source) is a complex number in the unit disk: Γ=0 is a perfect match (all transfers), |Γ|=1 is total mismatch (all reflects). A complex number carries magnitude and phase — "how much" and "which way" — which is exactly the tightness-vs-position split we insisted on.

Γ = 0                 ⇄  exactMatch     (perfect transfer, no penalty)
small |Γ|             ⇄  closeMatch     (mostly transfers, some loss)
|Γ| → 1               ⇄  no real match  (nothing transfers)
|Γ|  (magnitude)      ⇄  tightness      (HOW MUCH mismatch)
∠Γ   (phase)          ⇄  position       (WHICH WAY — inductive/capacitive ≈ broad/narrow)

VSWR / return loss          ⇄  scalar magnitude / demotion cost (one number for "how bad")
S-parameters / Smith chart  ⇄  per-dimension sub-scores, shown on demand (decomposed "why")
frequency band in use       ⇄  load-bearing (a mismatch only costs you IN the band you use)
matching network/transformer⇄  OCSF / pySigma pipelines (literally "impedance matching")
common ground / reference   ⇄  OCSF as the shared schema everyone is measured against
VNA calibration (SOLT)      ⇄  the grade is a claim needing validation; defns = reference plane

The load-bearing gate is the cleanest: impedance is frequency-dependent, Z(ω), and a mismatch only degrades your signal where your spectrum has power. A bad match at a frequency you don't use is inert — exactly "a closeMatch on a field the rule never reads doesn't demote."

Where it breaks — and the break is the point. Γ is a physical, measurable quantity underwritten by Maxwell's equations: you measure it, it's true. A semantic grade has no underwriting physics — there's no equation for "is ServiceName the same concept as Service_Name." The analogy gives the shape (graded, magnitude+phase, band-gated, calibrated, decomposable) but not the ground truth. Which is exactly why canon needs the parts a transmission line never does — justification, contestability, a peer-reviewed commons. A coax cable doesn't need its reflection coefficient peer-reviewed; a semantic edge does. The faint analog even there is metrology: trust via traceability to community-maintained reference standards (NIST). Reviewer credibility ≈ calibration traceability.

The grade is an inference over that ground: computable where the specs are formal (datatype / enum / value-domain → broad/narrow as set containment), judgment only in the residual (semantic identity not reducible to type + values, e.g. source_ip vs nat_ip; silent specs; intent). Canon already lives in EE on the detection side — the battery is radar/sonar DSP lineage (CFAR, matched filtering, conformal). This puts the same physics-borrowed thinking on the integration side. The matched filter maximizes SNR against a known template; impedance mismatch in that template degrades the correlation. Same family, one layer over.

8 · The open problem

When an edge flips to contested, every verdict that ever leaned on it load-bearingly is retroactively in question — a provenance-invalidation / re-derivation problem. Tractable precisely because everything is content-addressed and reconstructable, but it is the non-trivial part, and it is its own pass.

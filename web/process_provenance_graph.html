OS execution as a content-addressed PROV graph

The substrate's native input — wider than detection, and the same shape as canon.

canon · process provenance · 2026-06-05 · packages/detection/experiments/process_provenance_graph.py

A Sysmon process-create log is a flattened view of system-execution provenance: each event records a process, the binary it ran (with its hash), the user, the command line, and its parent. That is already a PROV graph — Entity / Activity / Agent. So the substrate ingests it natively, with no imaging or gridding (unlike point-process signals, which the battery must impose a grid on). Detection is one fold over this graph; the graph itself is wider — forensics, audit, causality, blast-radius all read the same object.

One-hash-three-roles, made literal. Canon's keystone — node id = provenance entity = custody digest — has been abstract (a CID over a computation node). Here it is a real binary hash: 
process : C:\Users\pupy.godoy\Downloads\winx64_payload.exe
user    : PANDALAB\pedro.gustavo          <- prov:Agent
parent  : C:\Windows\explorer.exe         <- prov:wasInformedBy
hash    : sha256:dfc6459d…1137ddd7        <- node id = provenance entity = custody digest
The hash is at once the node identity (same binary across hosts = one node), the provenance entity (what executed), and the custody digest (checkable against known-good / known-bad). The OS execution graph is where canon's central design idea is literally true.
Custody partially wakes up. Custody has been NONE all along because logs are unsigned — and the log's chain still needs signing. But the binary hash is checkable: a process's image hash can be matched to threat-intel (known-bad) or a baseline (known-good). That is binary-integrity (live now, for free, from the Hashes field), distinct from log-custody (still needs signing). The first real custody signal in the program.
What the structural view surfaced for free. winx64_payload.exe sits in pupy.godoy's Downloads but ran as pedro.gustavo — a credential pivot the flat log obscures and the provenance graph makes visible. Structure answers questions shape can't.

Why this is "almost canon, but wider and more native"

  • Same shape as canon. The graph is the substrate's own Entity/Activity PROV-O — the exact representation the provenance fold already emits. Detection is one fold over it; the justified verdict is one view of a flagged subgraph.
  • Wider. The execution graph serves forensics, audit, causality, and blast-radius — detection is one question you can ask of it, not the whole point.
  • More native. The battery must impose a grid on point-process logs to get shape (timing, volume) — lossy, the "imager" problem. A provenance-bearing log (parent→child links) needs no grid for structure (lineage, composition, reachability) — it is already a typed DAG. So the split is: structured, provenance-bearing logs are ingested natively; only signal / point-process data needs the imaging transform.

Prior art + honest scope

This is a mature field — whole-system provenance (CamFlow, which emits W3C PROV; SPADE) and provenance-based intrusion detection (the PIDS line). Canon's edge is not "we built a provenance graph" (everyone has) — it is the justification + honest-NONE layer on the graph: a flagged subgraph carrying its guarantee tier, its custody (binary-integrity live, log-custody NONE), and what it could not check.

Two honest limits. Proven vs potential — this is a 127-event slice on one host; native provenance ingestion is demonstrated, not yet a product. Scale — whole-system provenance is millions of events per host per day; storage and graph blow-up are the field's central struggle, which is exactly where the cost-fold / localize / coarse-first disciplines have to carry their weight (localize around flagged subgraphs; never materialize the whole graph).

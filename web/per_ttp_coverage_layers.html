Per-TTP coverage — atoms, compositions, catch-classes

A technique isn't covered by "≥1 rule." It's covered by a set of distinct checks — and the layer you count at decides what "covered" and "redundant" mean.

canon · design · 2026-06-19 · rule layer built · atom + catch layers pending

MITRE coverage is usually stated per technique — "do we have a rule for T1003.001?" That's the wrong granularity. A technique is detected by a set of distinct checks, and coverage is a property of that set. The content-aware signature work made this concrete: the old field-set key collapsed value-distinct checks into one concept and the round fired only one of them — silently dropping the rest (OTRF T1003.001: 33 field-set concepts → 74 content concepts, 41 distinct detections recovered). So per-TTP coverage is a layered count.

1 · The three layers

atom            (field, op, value)                   — one predicate over one event       — SHARED across rules/TTPs
  │  bonded by AND / cross-event join on a key
molecule/rule   block(s) + condition                 — a composition of atoms             — the authored unit
  │  grouped by what they catch
catch-class     rules firing on the same instances   — the true per-TTP variant set       — the ground truth
LayerWhat it isKey property
atom a compiled clause (field, op, value) — where to look, how to compare, what against (e.g. TargetImage endswith \lsass.exe). The smallest true/false on one event. Shared. Image endswith \rundll32.exe appears in dozens of rules across many techniques.
molecule / rule a composition of atoms: a block (AND/OR of clauses), a cross-event bond (spawn ⋈ access on ProcessGuid), and a condition (selection and not filter, 1 of sel_*, sequence-in-window). Elaboration varies — comsvcs is near-atomic; selection and not filter is a real composition. No "rule = primitive" assumption.
catch-class rules that fire on the same labeled instances — one variant of the detection, however written. The only layer that measures real coverage. Needs labeled instances (synthcyber-gated).

2 · The keys bracket the truth

The concept keys we have are structural proxies sitting at different layers; they bound the true variant count, none measures it:

KeyCollapsesPer-TTP effectRedundancy
field-setsame fields (value-BLIND) UNDER-counts variants (over-collapse)UPPER bound · 7.15×
content (built)byte-identical (field+op+value) enumerates at rule level; OVER-counts equivalents written differentlyLOWER bound · ~1.0×
catch-setsame instances caught the TRUE variant countthe real number
Report coverage as a bounded set, not a number. Until catch-set exists, per-TTP coverage is "a set of checks between the field-set lower bound and the content upper bound." Content fixed the round's recall by measuring at the rule layer; field-set was measuring the bug.

3 · The shared-atom firing model — the engine lever

A naive per-TTP sweep re-evaluates shared atoms many times: Image endswith \rundll32.exe is checked once per rule that contains it, across every technique swept. That's why "content-aware fires ~2× the rules" reads as a cost — it's only a cost under a per-rule engine. Factor the rules to their atoms instead:

1. collect the DISTINCT atom-set across all selected rules     (dedup is automatic — content-addressed)
2. evaluate each distinct atom ONCE over the data → cache      (event → {atom_id: bool})
3. evaluate each rule as a cheap boolean fold over the cache   (never re-touch the data)
Content-addressing makes step 1 free. An atom's content digest is its node id, so identical atoms across rules are one node — the Merkle dedup property. This is the IR-as-spine picture literally: atoms are the leaves of the content-addressed DAG, compositions are internal nodes, evaluate the DAG once. It dissolves the volume worry — more rules firing ≠ more atom evaluations once atoms are shared. (Not built: eval_ir is per-rule; atom-sharing is the next factoring and the scale architecture.)

4 · Redundancy: robustness vs correlation

Catch-set co-membership says two rules catch the same target. It does not say "drop one." Two rules catching the same instance via different structure are diverse paths — if one rule's field is absent (telemetry gap), renamed (the OCSF/CallTrace impedance), blanked by a naming mismatch, or evaded, the other still fires. That is N-version coverage. So a second axis decides whether redundancy is worth keeping:

atoms DISJOINT (independent paths)atoms SHARED (correlated paths)
same catch-class ROBUST redundancy — keep both. Real corroboration; survives a telemetry gap / evasion / rename. WASTEFUL redundancy — no added robustness, and over-counts confidence in Belnap fusion (the shared-evidence risk).
Atom-overlap is the classifier — and content-addressing supplies it. Two rules share evidence iff they share atoms (a shared sub-DAG). So the same factoring that makes firing cheap also decides which catch-set-redundant rules are independent witnesses (keep — they raise real confidence) vs correlated (don't). Witness independence, canon's flagged-open question for confidence fusion, becomes decidable structurally — by atom-disjointness.

5 · The model in one picture

per-TTP coverage = a set of catch-classes
   each catch-class = one or more rules (compositions) that catch the same instances
      each rule    = a composition of atoms (clauses bonded by AND / join / condition)
         atoms are SHARED across rules and TTPs → evaluate once (content-addressed dedup)
   keeping >1 rule per catch-class is justified IFF their atoms are disjoint (independent witnesses)

6 · Status

  • Built — rule layer: the content-aware signature (CompiledRule.content_digest, content_signature), wired into select_detections and the audit. Recall fix proven (33→74 on OTRF T1003.001).
  • Not built — atom factoring: evaluate the distinct atom-set once, cache, compose. Pure engine work, corpus-free; an atom-level content digest is the small addition (today the digest is per-rule).
  • Not built — catch-class: the true per-TTP variant count and same-catch grouping. Gated on the labeled-instance generator (synthcyber).
One line. A technique is covered by a set of distinct checks, not one rule; rules are compositions of shared atoms, so fire the atoms once and compose; and redundant catchers are worth keeping exactly when their atoms are disjoint — independent witnesses, decidable by content-addressing.

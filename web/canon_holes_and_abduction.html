Canon's holes — and what "abduction" means

Where the substrate actually stands, and the concept naming its biggest gap.

canon · state node · 2026-06-13

Context: the Kaggle competition (parked)

This node grew out of looking at the Kaggle AI Agent Security — Multi-Step Tool Attacks competition (OpenAI/Google/IEEE): an algorithmic red-teaming task where you build a search that finds multi-step poisoned-input chains making a tool-using agent cross a security boundary. After working through it, the honest verdict: it is **largely exterior to canon.** The one genuinely transferable piece is Go-Explore (a generic archive-based search algorithm) for canon's missing orchestration layer; the rest — its labeled traces (agent-tool domain, not host telemetry), its eval harness, its taint-shaped predicates — is either wrong-domain, generic, or something canon already has in richer form. Likely not pursuing it — the focus is core canon. Parked here as the context this node came from.

Canon's holes, honestly

  1. No proposer. Canon is all verifier — deductive pattern-matching over the provenance graph. The hypothesis-forming step (the abduction loop's STITCH) is unbuilt. Canon can check a claim; it can't form one. (the concept below names this)
  2. No orchestration. The six detection cells are isolated. Nothing decides which to fire when — the firing-order / investigation-DAG search. This is the one place Go-Explore could help.
  3. No real evaluation. Everything runs on one OTRF corpus (+ synthetic). The "does a finding mean anything real" question (operational value) is open — no ground truth, no multi-corpus test.
  4. The (who, job) root is undefined. The keystone's hard, out-of-band part — pinning legitimate authority / the baseline — is unbuilt.
  5. It's experiments, not a product. The cells live in packages/detection/experiments/, not an integrated system. (Plus: custody inert — no signed feeds; no streaming; the agent-tool domain designed but unbuilt; the machine-checked proof tier a deferred absence.)
The biggest is #1 + #2: canon has a solid verifier substrate and no engine that drives it. It is the conscience without the imagination.

Why "abduction," and what we're "abducting"

Nothing gets kidnapped — it's the logic term. Charles Peirce's three modes of inference:

modeshapenature
deductionrule + cause → effect ("if A then B; A; so B")certain
inductionmany cases → general rule ("lots of A were B, so A's are usually B")generalization
abductioneffect + rules → best cause ("B happened; A would explain B; so probably A")a defeasible guess

Abduction is inference to the best explanation — reasoning backward from observed evidence to the most likely cause. In the loop: given grounded atoms (the events — the evidence), the LLM abduces the best explanation of what happened ("this is a credential dump that moved laterally"). What we "abduct" is a hypothesis from the evidence, not an object.

The name is exact because detection is fundamentally abductive: from logs you infer the best explanation of an attack, and that inference is a guess, not a proof — which is precisely why it is the LLM's job (generative, uncertain) and why it must then be verified. Abduction proposes; deduction checks. Canon today has only the second half — which is hole #1, in one word.

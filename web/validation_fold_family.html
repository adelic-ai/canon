The substrate is an open family of validation folds

Not one validator — however many independent lenses make sense, over one object.

canon · architecture · 2026-06-05 · packages/provenance · contracts/

A result is not just a number. The substrate takes a computation expressed as one content-addressed graph and reads it through many independent lenses — each a fold that answers a different question (what is the value? how was it made? can the inputs be trusted? what wasn't checked?). The lenses compose because they share a shape, and the family is open: add as many concerns as make sense, provided each one passes a single membership test.

Three axes — easy to conflate, kept distinct

AxisShapeMembers
Folds = concernsparallel, independent value · provenance · custody · validity · guarantee · confidence · temporal (+ cost, named-not-built)
Tiers = rigorstacked (a partial order) well-formed → bounded → machine-checked (within the guarantee fold)
Data-components = wheredisjoint vantages host · network · cloud · auth (which sensor saw it)

"However many validation layers make sense" is the first axis — the open, extensible fold family. The other two are not stacks of validators; they are the rigor ladder inside one fold, and the observation tier the data arrived from.

The membership test — what keeps "however many" honest

A candidate concern is admitted iff it can be written as a ≤_k-monotone fold over the graph into the Belnap carrier — and that is CI-checkable. Feed it NONE / BOTH and assert no knowledge-order violation. If a concern can't be written monotone, it is rejected and re-cut. So the family is open but not arbitrary: monotonicity is the gate.

The governing sentence. Every cross-cutting concern is a ≤_k-monotone fold from one content-addressed computation graph into a Belnap bilattice. That single idea is the joinery: the folds compose because they share a shape, the acceptance test ("add concern N without touching concern M") is monotonicity, and the justification of a result is the same object as the result.

The carrier — why a fold can say "I couldn't tell"

Every fold computes in Belnap's four values, so each lens can be honest about absence and contradiction — the thing ordinary validators can't express:

TRUE
we looked, it holds
FALSE
we looked, it's clean / fails
NONE
we couldn't see (≠ FALSE)
BOTH
our checks disagree

The knowledge order NONE ≤ {TRUE,FALSE} ≤ BOTH is the formal statement of absence of evidence ≠ evidence of absence. Combining evidence can only move up — that is the monotonicity every fold must obey. BOTH is not averaged away; it is wired to the self-falsification machinery as a soundness alarm.

A verdict is a domain view that selects which folds matter: detection picks {technique, custody, cross-check, calibration}; a data pipeline might pick {lineage, validity, freshness}; finance {value, confidence-interval, custody-of-feed}. The folds are the agnostic core; the verdict is a thin per-domain selection over them.

Honest scope. The fold family is built in packages/provenance and is domain-agnostic by construction. But "open and extensible across domains" is demonstrated only within detection so far — new concerns and new domain verdict-views are designed, not yet exercised. And several folds are out-of-band-dependent — custody is live only with signing, confidence only with known operating points — so the family lights up differently per domain rather than uniformly.

One Package, All of Sigma

The FCA/SKOS rule-sameness pipeline, end to end — reviewable piece by piece.

a standalone package · every stage a module · every module a review gate

Doing it over, properly. Not the macOS slice and not throwaway scripts — one clean, standalone package that runs the whole thing over all 3,748 Sigma rules, built and reviewed one stage at a time.

The job, end to end: consume every Sigma rule → lower it to a normalized IR → derive FCA concepts at each attribute granularity → express the graded relations as SKOS → report the over-collapse and its generalization, and emit the RDF.

The honesty hinge is coverage. Parse is not where rules are lost — pySigma reads the corpus whole (below) — so the honest denominator sits downstream, at analysis coverage: which rules yield meaningful attributes, which we can fire. The report accounts for it per stated reason, never a silent filter.

Ingest — pySigma, not the CLI

sigma-cli is a conversion tool (rule → Splunk/ES query); scraping its output is the wrong layer. The right tool is the library it sits on — pySigma — which parses each rule into a real AST: fields, modifiers, values, the boolean condition. We delegate parsing to it and keep the package to what it is for — the analysis.

Why it earns "all of Sigma." Our own subset-parser abstained on ~40% of rules; pySigma parses the full spec — every modifier, correlation, rule collections — so no rule is lost at the gate. Verified live: 3,748 / 3,748 parse, zero errors. The honest denominator then moves downstream, to which parsed rules yield usable attributes.

Boundary kept explicit: pySigma parses, it does not fire. Structure — this package, part one — needs only the parse; firing rules for the catch-set (part two) is a separate choice, not forced by the parser.

Architecture — the IR is the waist

Ingest is inherently per-ruleset: Sigma → pySigma, CAR → data-model, Elastic → EQL, ESCU → SPL. There is no ruleset-agnostic parser. So the Sigma-specific code lives in an ingest/ adapter, and the IR is the boundary it cannot cross: below the IR, one adapter per language (parse + lower); at the IR, the languages converge; above it — axes, FCA, SKOS, report — omega is written once, ruleset-agnostic.

A second ruleset is a new module under ingest/ — car.py, elastic.py — not a reshaping. Nothing above the IR knows a rule was ever Sigma.

Stage 1 Map to attribute-IR ingest/sigma.py → ir.py

The adapter's second half: walk pySigma's parsed AST — SigmaDetectionItem (field, modifiers, values), each block's polarity, the boolean condition, logsource, tags — and lower it to the agnostic IR in ir.py: the (field, mods, values) atoms the axes read. Parsing and mapping are the Sigma adapter's; the IR they produce is everyone's. After this, no SigmaRule escapes.

to_ir(SigmaRule) → CompiledRule
new · the real seam

Because pySigma parses everything, even rules we cannot yet fire (base64, fieldref, correlation) still yield attributes — parse-for-clustering, separate from evaluate-for-firing.

Stage 2 Attribute axes axes.py

From the IR, extract the attribute set at a chosen granularity — the "one real knob," made first-class: field_set (value-blind) · clauses (value-aware) · polarity (selection + filters) · relational (fieldref pairs).

attributes(ir, axes=…) → frozenset[attr]
new · consolidates
reviewTurning axes on/off does exactly what the essay claims — coarse to fine.

Stage 3 FCA concepts fca.py

Group rules into concepts by their attribute set and compute the broader/narrower subsumption order and the concept counts. The over-collapse numbers are born here.

concepts(rules, axes) → partition + ⊆-order + counts
new

Uses the tractable partition + order (what the essay actually uses), not the full Galois lattice — that is exponential and pointless at this scale. A deliberate cut.

reviewValue-blind vs value-aware concept counts, per product and corpus-wide.

Three decisions before Stage 0

  1. Name + location. Suggest packages/rulesame/ — or sigma_sameness, or tie it to the series. Your call.
  2. Standalone, pySigma the one dependency. (settled) Parsing is delegated to pySigma rather than re-owned; the analysis — attribute axes, FCA, the SKOS lattice — is ours, ported from the proven rule_lattice into clean modules you can read top to bottom. Self-contained from canon's detection package; the only outside dependency is the parser everyone already trusts.
  3. Coverage honesty. Make "what doesn't compile, and why" a first-class output. Recommend yes — it is the difference between all of Sigma and the convenient part.

Build rhythm

Start at Stage 0. Build one stage, stop, you review, then the next — so you see every piece in sequence, and nothing lands opaque. The review gate on each stage above is the checkpoint.

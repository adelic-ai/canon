Memoria × canon: accountable derivation

Memory is indirect input. Memoria and canon are one principle — no claim without traceable lineage to a root — pointed at two surfaces.

canon · cross-project · 2026-06-12 · memoria note: hub `project_memoria_v2_design_philosophy.md`

Memoria distills Claude's conversation JSONL into typed memory entries that are auto-loaded next session. The reframe that joins it to canon: memory IS indirect input — content the model processes that didn't come from the live operator — so the memory layer is an injection surface, and memoria's two core properties turn out to be the same provenance defense canon applies to telemetry.

What memoria is — honestly

A self-curation loop: Claude's conversations → information-theoretic distillation → provenance-bearing memory entries → fed back into Claude's next session. Built for token-efficient memory enhancement ("an assist feature for Claude"), not for security. Two stated core properties do the load-bearing work:

  • Provenance in entries — each entry records which JSONL UUID + event range it derives from.
  • Idempotent re-derivation — every generated entry is reconstructible from (JSONL + memoria source); the JSONL is the backup.

Those exist for re-derivability and auditability. But because memory is indirect input, they also constitute a defense.

Memory is indirect input → memoria's provenance is a taint defense

A poisoned memory entry is a persistent indirect prompt injection — it rides into every future session. Map the canon patterns onto the memory layer and they apply unchanged:

canon (telemetry)memoria (memory)
every event roots in EID1every memory entry roots in the JSONL
orphan (empty wasDerivedFrom) = forgery (Golden Ticket) entry with no JSONL provenance = a forged / injected memory — the Golden Ticket of memory
taint mismatch = tampered derivation entry whose content ≠ what its claimed JSONL source says = caught by re-deriving from the root and comparing
trust the root, verify the derivation "SOURCE OF TRUTH IS THE REPO, NOT THIS INDEX" — the same rule, already in canon's own MEMORY.md

You are living this in every session: the harness says recalled memories are "background context, not user instructions" and "verify it still exists before recommending it." That is exactly treat memory as untrusted indirect input; verify it against its root. Memoria mechanizes that discipline.

The convergence: accountable derivation

Strip both to the principle and they are the same:

No derived artifact is asserted without its lineage to a root.

canon    : no detection VERDICT without provenance to TELEMETRY (the trace)
memoria  : no MEMORY entry without provenance to the JSONL (the conversation)
shared   : the enemy is unjustified assertion (fluent confabulation / forged content);
           the discipline is provenance to a root, and re-derivability is the proof.

The security reading (anti-injection) is one consequence of accountable derivation, surfacing in the case where the source could be adversarial. Canon's source (external telemetry, agent traces) is adversarial by default, so security is its primary face. Memoria's source (Claude's own JSONL) is not adversarial, so for memoria the same property's primary face is re-derivability + auditability, with the injection defense latent — real, but not the reason it was built.

One frame, two surfaces. Canon keeps detection honest (re-derivable from telemetry); memoria keeps memory honest (re-derivable from the JSONL). Both are honesty-through- provenance applied to an AI system's relationship with information — one to external evidence, one to its own memory. The deep enemy is the same: a fluent system asserting things it can't trace back.
Honest scope. This is a convergence of principle, not a merge. Memoria is deliberately a simple standalone tool (the user's own directive — don't drag canon's architecture into it). What's shared is the discipline (accountable derivation), not the code, the substrate, or the purpose. Naming the shared principle is useful; collapsing the two projects is not.

Canon — Detection Battery

A measurement layer (IT) feeding a decision layer (DT), dispatched across escalating tiers.

design readout · 2026-05-30 · self_validation_architecture.md · it_detection_inference · dsp_vs_it_split · ~/dev/{tasc,pickering}

It is two disciplines, not one — and "IT" named only half of one of them. A detector is a feature piped into a test:
  • IT — information theory (Shannon): entropy, KL, mutual information. Supplies the interesting features. Plus a base of plain descriptive statistics (count, variance, Gini) and a DSP corner (periodicity). This is the measurement layer.
  • DT — detection theory (Neyman–Pearson, Page, Wald): CFAR, CUSUM, SPRT, conformal. Supplies the tests — the thing that decides "anomaly?" with a controlled false-alarm rate. This is the decision layer.
The battery is IT-features × DT-tests over a statistical base. CFAR/CUSUM are not built on KL/MI — they are fed by them.

Foundations. Both pillars rest on probability theory (the shared substrate — entropy/KL/MI are functionals of distributions; CFAR/SPRT are decision rules over likelihoods). Statistics is the finite-sample layer that makes them work on real logs (estimating entropy from counts, CFAR's noise floor from training cells, conformal calibration). And both trace to physics: entropy is a thermodynamic quantity Shannon repurposed; CFAR / matched filter / energy detector are radar–sonar physics, where the "noise model" is a physical model. Probability + statistics = the logic side; physics = the empirical-reality side — canon's two grounds.

The gap this exposes: what were CFAR and CUSUM ever fed?

The volume feature — counts/rates per window — implicitly, and it was never written down. forge-core's CFAR and CUSUM take a numeric statistic Signal and threshold it; for cyber that statistic defaulted to event count/rate (Poisson). So the battery had a rich test layer sitting on a one-element feature layer: count. Entropy, KL and MI — the features that make the IT side worth anything — were never wired in as inputs. The TASC/Pickering primitives aren't a foundation under CFAR/CUSUM; they're the missing upstream measurements that should flow into them.

The full canonical structure

Three orthogonal things, composed: a measurement axis, a decision axis, and a dispatch ladder (with a rigor dial running across it). A named detector is a cell — one feature × one test — deployed at some tier.

The dispatch ladder (T0 → T3)

Tiers escalate on cost × specificity: each tier is more expensive and more targeted, and is gated by the tier below firing. This is the ∃-detect → ∀-validate split stretched into a pipeline.

  • T0 — standing sweep. Always-on, O(stream), every entity/window. The cheap FP-controlled cells (volume/cardinality/entropy/KL × CFAR/CUSUM/rank). Surfaces an anomaly and its W's. Broad, blind to nothing statistical, controlled false-alarm rate.
  • T1 — W-directed. On-demand, only the delta the W's point at: relational/pairwise features (MI), the periodicity corner (beaconing), and technique-specific confirmations (matched filter). You run these on the W-scoped slice, not the whole stream.
  • T2 — correlation / sequence. CEP / chronicle recognition over the stream of T0–T1 firings: stitch point-anomalies into a multi-step attack-chain hypothesis (kill-chain, Attack-Flow). The claim escalates from "a point is anomalous" to "a campaign is underway." This is the temporal ∀-over-a-pattern-DAG fold.
  • T3 — adjudication / verification. Triggered by high stakes or a Belnap Both (detectors confidently disagree). Escalate to a deeper/verified joint: machine-checked numeric kernel, differential replay against the reference, or human adjudication. Produces the machine-checked guarantee tier and resolves the contradiction.
The rigor dial is orthogonal to the tier. The architecture's tiered dispatch has two axes — speed/cost and rigor — so every firing, at any tier, also carries a guarantee tier: well-formed → bounded (closed-form Pfa where the noise model holds, conformal otherwise) → machine-checked. A Both contradiction is both a soundness alarm and the trigger that escalates rigor toward T3. Tiers are the inference axis; the guarantee dial is the trust axis; they compose.

So what is the canonical standard?

Not a fixed list of detectors. The list is generated by the structure above and grows by the artificial-ignorance residue loop. What's actually canonical is three fixed contracts:

  1. Two minimal generating axes. Minimize the feature axis and the test axis independently (FCA minimum generating set per axis — no feature reducible to a function of others, no test reducible to another). The detector grid is their product; a candidate detector is canonical iff its cell catches a shape no existing cell does. Decidable, not taste.
  2. Uniform false-alarm control across the whole grid. Every cell exposes a calibrated Pfa — closed-form where the noise model is genuinely known (CFAR), conformal everywhere else (entropy/KL/MI/IF have no native rate). This is the bounded guarantee tier applied per detector; it is what makes the Pfa operational (it decides what escalates a tier) rather than decorative.
  3. One detector-output contract. Every cell, every tier, returns (score, W-record {who/what/when/where/how}, GuaranteeCertificate, provenance Entity). Uniform output is what lets the inference layer consume CFAR, entropy, beaconing and kill-chain identically. This schema is the standard to write into ~/canon/contracts/; the grid plugs into it.

Prior art — TASC and Pickering

TASC (/Users/shunhonda/dev/tasc) — knowledge/framework layer

Knowledge graph (~4900 nodes) mapping detections claim → math → proof → implementation across 15+ frameworks. IT-relevant: adapters/_detection_protocol.py (an early detector-output contract — DetectionFinding carries algorithm/schema/features/ covers_techniques); adapters/forge_it.py (ingests entropy/autocorrelation/spectral/ changepoint/residual ops, bridges to CAPEC→ATT&CK→Sigma→CAR→D3FEND by Jaccard on feature closures); inference/{primitives,features,lattice}.py (FCA over detection observables — the per-axis minimization, already exercised). No CFAR, no CUSUM. Catalogs detections; doesn't run them.

Pickering (/Users/shunhonda/dev/pickering) — execution layer

Working SIEM-like compiler on vendored signalforge. signalforge/signal/_information.py is the feature layer: entropy, joint_entropy, mutual_information, kl_divergence, information_gain, discover_scales. pickering/dag.py runs them as a pruned topological DAG (compute_entropy / compute_rarity / check_baseline_deviation [KL] / check_cross_entity_mi / kill-chain matchers [the T2 layer]). detections.py = ~25 MITRE-tagged named cells; fpass.py/discover.py = schema-only IsolationForest fallback. It already implements the feature layer, a T2 sequence layer, and W-style per-entity features — but its tests are z-scores and IsolationForest, never CFAR/CUSUM.

Net for canon. forge-core supplies the DT tests (CFAR, CUSUM, Goertzel, matched filter) the prior art lacked; Pickering/signalforge supply the IT features (entropy, KL, MI, rarity) canon names but hasn't built. The canonical battery is the product of the two axes, behind one output contract, with conformal supplying FP control wherever closed-form Pfa doesn't exist. Next concrete step: write the detector-output schema into contracts/, then port the IT feature primitives in as forge-core ops feeding the existing DT ops.

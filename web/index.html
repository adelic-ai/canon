Online Partial-Chain Detection: the Third Stateful Shapenew A completed kill-chain is a failure (the jewel is gone), so the thing to detect is the unfinished prefix — and firing on prefixes changes what you persist from the path to per-entity partial-match state. Rules & Sigma

Three Notions of "the Same Rule" Three distinct equivalence relations on rules that don't coincide: same conditions (clause_set — the lattice's ⊆/∩ relationships, blind to filters/wiring), same construction (content_digest — byte-identical logic, the finest), same behavior (catch-set — fires on the same instances, the only one about what a rule DOES). Same-conditions and same-behavior are incomparable; the over/under-grouping bugs are exactly where they disagree, which is what ground_lattice maps. The durable point: the bugs live in the gap between what a rule says and what it does — so you need the structural view to scale, the behavioral view as truth, and the comparison as an irreducible step. The Sigma Rule Lattice: What the Corpus Actually Looks Likeresult The SKOS-graded lattice run over 333 rules (3 techniques): 1 true synonym, ~22 subsumption pairs, 633 loose overlaps (96%). So Sigma doesn't dedup into clean categories — it's a graded relation graph. The actionable structure is the subsumption families (a general rule like "Non-Interactive PowerShell" → its stricter variants: ConvertTo-SecureString, CrackMapExec, base64…). Tables of the families (category→members) + the exact-match dedup classes. All structural; catch-set grounding would correct the edges. Resolution: What We Built to Sharpen Sigma, and What's Leftexploration The treated corpus is an instance — a result warranted only relative to (corpus, code, labels) — so every "categorize Sigma" tool is really a resolution instrument. Five axes, each trading lossy for fine, all running claim → structure → behavior: what a rule detects (tag → FCA → IR → catch-set), how rules relate (dedup → SKOS lattice → tightness → co-catch arbiter), the Belnap carrier, schema-mapping fidelity, miss-diagnosis. What's next: filter/value-aware content_digest (no new data), catch-profile-not-set, cross-corpus ablation. The honest cap isn't a construction — it's data shape (atomic captures are pure-attack). Adoption & integrations

Adoption: Get In Where We Fit, Then Dissolve Into Positionnew You don't know how an enterprise is set up, so the entry point is theirs, not yours. Four seams to hook in (rule layer = ingest their detections → IR; data layer = OFF-able OCSF waist; verdict layer = wrap their alerts with warrant, lowest friction; storage = columnar over their lake). Be useful day one via the read-only seams (coverage scorecard, warrant-wrap). Then dissolve into position: read-only → shadow → incremental takeover → IR canonical. The trust wedge is the attestation gates — "I run your detections identically, provably, and add justification you didn't have." Embrace-and-extend done honestly. An Enterprise Entrypoint: Mine the Detections and Their Allowlistsidea An idea. Read as a positive map instead of a suppression list, the allowlist becomes the watch set (the privileged/automated surface an attacker rides). Feed the detection logic + the allowlist-derived identities into the substrate → enterprise-specific atoms to fire → entail ATT&CK + the kill chain on them. An entrypoint built entirely from artifacts the enterprise already runs.

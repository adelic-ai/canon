The Sigma rule lattice — what the corpus actually looks like

Not clean categories. A graded relation graph: a few true synonyms, a thin subsumption skeleton, and a dense web of loose overlap.

canon · result · 2026-06-20 · 333 structured rules · T1003.001 + T1547.001 + T1059.001 · the SKOS-graded rule lattice

The flat field-set "FCA" key grouped rules into "concepts" by which fields they read — and over-collapsed, folding value-distinct detections into one. The content-aware SKOS-graded lattice instead relates every pair by what it matches: exactMatch (true synonym), broadMatch/narrowMatch (subsumption — a navigable order), relatedMatch (overlap, IDF-graded). Run over 333 structured rules across three techniques, here is what the corpus actually is.

The shape — dedup is rare; structure is graded overlap

RelationSKOSedgesmeaning

broaderskos:broadMatch17 a general rule subsumes a stricter one
narrowerskos:narrowMatch5 the stricter side of the same relation
relatedskos:relatedMatch633 share a clause or two, neither subsumes — 96% of all edges, IDF-tightness median 0.14 (uniformly loose)
The headline finding. Of 657 relations, only 1 is a true synonym and ~22 are subsumption; the other 633 are loose overlap. So the corpus does not partition into clean categories — it's a web of rules that share a clause but each detect something distinct. The flat field-set key would have collapsed much of that 633 into "equivalence classes" by shared fields — conflating overlap with equivalence. The graded lattice is what tells them apart. (exactMatch is structure-aware: it requires identical composition, not just identical clauses — so the one pair that shares clauses but composes them differently is closeMatch, not a synonym.)

Categories that genuinely exist (2) — the true synonym (the only real dedup)

One pair out of 333 rules. "Dedup" — the thing the flat key claimed lots of — is almost nonexistent at the content level. The previously-counted second pair (Alternate PowerShell Hosts Pipe / New PowerShell Instance Created) is now closeMatch, not exact: they share clauses but compose them differently, and structure-aware exactMatch no longer calls that a synonym.

What the result means

  • The corpus is a graph, not a partition. 96% of relations are loose overlap, so "categorize Sigma" is the wrong frame — the lattice relates, it doesn't cluster. The product is the relation graph (emitted as a SKOS RDF graph: SELECT ?a ?b WHERE { ?a skos:broadMatch ?b } for the subsumption skeleton).
  • The subsumption families are the actionable structure — general surface + stricter variants; the order tells you which to fire for precision vs recall.
  • This is all structural (what rules match), not behavioral (what they catch). Two rules can be lattice-"related" yet catch totally different instances, or lattice-disjoint yet catch the same attack via different fields. The catch-set grounding (run rules over labeled telemetry, group by co-caught instances) is what would correct these edges — the keystone, gated on labeled data.
One line. Across 333 rules the corpus is 1 synonym, ~22 subsumption pairs, and 633 loose overlaps — so Sigma doesn't dedup into categories; it forms a graded relation graph whose only clean structure is the subsumption families (general rule → stricter variants), and whose true grouping awaits catch-set grounding.
